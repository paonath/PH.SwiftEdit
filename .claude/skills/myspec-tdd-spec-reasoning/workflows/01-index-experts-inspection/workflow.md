# Workflow 01: Index Consultation, Domain-Expert Enrollment & Codebase Inspection (`myspec-tdd-spec-reasoning`)

1. **MANDATORY Index, Always-Read, Constitution & Living-Spec Consultation (`<spec_root>/index.yml`, `<spec_root>/Constitution.md` & `<specs_dir>/<capability>/spec.md`)**:
   - Read `<spec_root>/index.yml` (default: `openspec/index.yml`, fallback: `specs/index.yml`) BEFORE scanning the repository to save search steps and context tokens.
   - Read EVERY document listed under `always_read:` in `<spec_root>/index.yml` and explicitly correlate its constraints and domain rules with the user's prompt.
   - **Mandatory Constitutional Authoring Gate (`Single-Reference Lock`, `SDD-001`..`SDD-003`)**: When `<spec_root>/Constitution.md` exists on disk, read `<spec_root>/Constitution.md` (`<= 45` lines), load ONLY the matching `<NN-area>/index.md` (`<= 25` lines) and at most 1 atomic micro-file (`<= 40` lines) per active expert/scope under `Single-Reference Lock`, and embed explicit active `[<PREFIX>-###]` rule citations across all 6 OpenSpec change artifacts (`proposal.md`, `design.md`, `specs/<cap>/spec.md`, `tasks.md` as `[Const: <PREFIX>-### (<NN-area>/<file>.md)]`, `test-plan.md`, `threat-model.md`).
   - Inspect the prepend-ordered `specs:` list in `<spec_root>/index.yml` (newest at top, oldest at bottom) using its minimal fields (`id`, `status`, `date`, `capabilities`, `path`, `summary`) to identify which existing specifications to read in depth for this development or change request.
   - **Pre-Spec Consolidated Living-Spec Comparison**: Read `<specs_dir>/<capability>/spec.md` for every affected capability and compare the requested behavior against already-consolidated requirements (`REQ-xxx`, `SEC-xxx`, `BC-xxx`, `AR-xxx`, scenarios, and `- **Trait**: security`). Explicitly classify whether the new specification introduces net-new requirements (`ADDED`) or alters prior consolidated specifications (`MODIFIED`, `REMOVED`, or `RENAMED`), and verify Living-Spec Rule G3 whenever a security or `BC-###`/`AR-###` boundary requirement or scenario is touched.
2. Analyze the feature prompt to identify technical domain(s) (e.g. C#/.NET via `dotnet-expert`, Angular/TypeScript/Node.js via `angular-expert`, Python via `python-expert`, Bash/Zsh/CMD/PowerShell via `shell-expert`, SQL via `sql-schema-planner`) and any business/scientific domain. When a change spans multiple Bounded Contexts, Aggregates, Sagas/Process Managers, or cross-module boundaries, enroll `ddd-expert` (`the domain-driven-design skill` under `Single-Reference Lock`).
3. **MANDATORY**: Enroll the matching stack expert agent(s) (`dotnet-expert`, `angular-expert`, `python-expert`, `shell-expert`, each hydrating its progressive-disclosure `*-architect` skill under `Single-Reference Lock`), and inspect `<spec_root>/agents/<domain-slug>.agent.md` for existing specialized non-stack domain expertise. Obligatorily load `the ears-syntax-standards skill` and `the bdd-gherkin-specifications skill` for AI-to-AI contract authoring and requirement modeling. If present, re-enroll the domain expert directly by loading stored directives (cache-recall). Otherwise, enroll a specialized `domain-expert` sub-agent for the domain, ingesting relevant briefs, and persist formulated expertise into `<spec_root>/agents/<domain-slug>.agent.md` upon completion (< 400 words).
4. Conduct deep silent codebase exploration following the `tokensave-first` rule:
   - **Production Source Code**: Inspect entities, services, API endpoints, data models, and static dependencies (`DateTime.Now`, `File.*`, `HttpClient`).
   - **Test Infrastructure**: Inspect existing test runners, frameworks (xUnit, MSTest, NUnit, Jest, Vitest), naming patterns, and mocking libraries.
5. Pre-fill all facts evident from the codebase so the user is never asked about existing project structure or framework versions.

## Normative Requirements (EARS)
- WHEN initiating Phase 1, the Inspection Workflow SHALL consult `<spec_root>/index.yml`, `always_read` entries, `<spec_root>/Constitution.md`, and affected living specs before repository scanning.
- The Inspection Workflow SHALL enroll matching stack and domain experts and load `the ears-syntax-standards skill` and `the bdd-gherkin-specifications skill` for AI-to-AI contracts.
